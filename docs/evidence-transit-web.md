# 浏览器中的证据区间通行

“法向证据确认的区间通行时间”使用已有测量结果，按协方差法向带确认门的侧别，再配对同目标、同片段的入口和出口。它保留两次过线的原始观测区间和均值弦插值估计，不换算速度；时间范围不是概率置信区间。

## 运行与回放

1. 载入仓储示例，完成普通测量。展开“法向证据确认的区间通行时间”，点击“仓储区间配置”，再点击“使用普通测量”。示例配置见 [evidence-transit-source.json](../examples/evidence-transit-source.json)。
2. 也可先运行“健康门控与法向证据联合分析”，在本区配置对应会话的门与区间，然后点击“使用三方门控测量”。所有测量帧都会转交核心，包括健康阻断、标定替换产生的空帧；待入口不能跨这些中断续接。
3. 结果跟随所选上游的回放滑块，显示当前帧累计数、待出口数量、完成通行、取消原因和法向侧别证据。表格在窄屏内横向滚动。

本区配置独立于原通道输入、独立法向证据输入和原区间统计配置。它不使用旧健康门控或测量＋证据联合分析的结果槽。选择另一来源成功后才替换本区结果；核心拒绝输入时保留已有有效显示。

配置首层为 `counting`、`sections` 和可选 `max_duration_us`。`counting` 是完整原始法向证据配置或恢复起点的 JSON **字符串**，其中的 `counting` 再包含原始门配置字符串。法向策略省略 `sigma_multiplier` 时使用核心默认值 2。页面显示核心返回的实际 k、σ、法向带和侧别，不重新计算侧别。

## 保存和续接

“下载证据区间结果”保存整批 `frames` 和同一批末帧的完整独立 `checkpoint`。“保存末帧证据区间检查点”始终保存批次末帧，与当前回放滑块位置无关。

检查点格式为 `moonground.evidence-transit`，包含完整法向证据计数器、证据参考点协方差、区间配置、累计完成数，以及待入口的过线记录和两端协方差。它不包含上游测量或地标健康状态，不与原 `moonground.transit` 检查点互换。

续接时分别保存同一原始时钟水位的上游检查点和本区检查点。上游从该水位处理更晚观测后，载入本区完整检查点，再显式选择仅含更晚帧的上游结果。页面先将检查点原文交核心完整验证，成功后才替换本区配置；不会修改上游输入、自动删除旧帧或重写时间戳。核心检查帧结构、会话、时间顺序和区间状态的内部一致性；续接数据需沿用原米制坐标系及原时钟。

输入配置修改会清本区结果。上游变化只使依赖该来源的本区结果失效；其他来源和原统计结果分别保留。后来的配置、文件导入或来源选择会取消旧准备，迟到操作不会覆盖新草稿。

## 与已查生态能力的关系

本批核对限于 Mooncakes 官方搜索与以下公开 API：[MBMOT 0.3.1 analytics](https://mooncakes.io/docs/python123-ops/mbmot@0.3.1/analytics)、[Moon-Kalman 0.2.1](https://mooncakes.io/docs/Lyllyl789/moon-kalman@0.2.1)。前者提供过线、区域转换及按帧停留，后者提供协方差、ConfidenceBand 和滤波检查点。所查 API 未见“法向协方差确认的双门通行＋原始时钟观测区间＋完整独立检查点”这一组合；该结论不覆盖整个 registry。
