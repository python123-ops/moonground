# 浏览器中的证据区间通行

“法向证据确认的区间通行时间”既可消费已有测量结果，也可直接联合处理原始观测。它按协方差法向带确认门的侧别，再配对同目标、同片段的入口和出口，保留两次过线的原始观测区间和均值弦插值估计，不换算速度；时间范围不是概率置信区间。

## 运行与回放

1. 载入仓储示例，完成普通测量。展开“法向证据确认的区间通行时间”，点击“仓储区间配置”，再点击“使用普通测量”。示例配置见 [evidence-transit-source.json](../examples/evidence-transit-source.json)。
2. 也可先运行“健康门控与法向证据联合分析”，在本区配置对应会话的门与区间，然后点击“使用三方门控测量”。所有测量帧都会转交核心，包括健康阻断、标定替换产生的空帧；待入口不能跨这些中断续接。
3. 结果跟随所选上游的回放滑块，显示当前帧累计数、待出口数量、完成通行、取消原因和法向侧别证据。表格在窄屏内横向滚动。

本区配置独立于原通道输入、独立法向证据输入和原区间统计配置。它不使用旧健康门控或测量＋证据联合分析的结果槽。选择另一来源成功后才替换本区结果；核心拒绝输入时保留已有有效显示。

配置首层为 `counting`、`sections` 和可选 `max_duration_us`。`counting` 是完整原始法向证据配置或恢复起点的 JSON **字符串**，其中的 `counting` 再包含原始门配置字符串。法向策略省略 `sigma_multiplier` 时使用核心默认值 2。页面显示核心返回的实际 k、σ、法向带和侧别，不重新计算侧别。

## 保存和续接

“下载证据区间结果”保存整批 `frames` 和同一批末帧的完整独立 `checkpoint`。“保存末帧证据区间检查点”始终保存批次末帧，与当前回放滑块位置无关。

检查点格式为 `moonground.evidence-transit`，包含完整法向证据计数器、证据参考点协方差、区间配置、累计完成数，以及待入口的过线记录和两端协方差。它不包含上游测量或地标健康状态，不与原 `moonground.transit` 检查点互换。

续接时分别保存同一原始时钟水位的上游检查点和本区检查点。上游从该水位处理更晚观测后，载入本区完整检查点，再显式选择仅含更晚帧的上游结果。页面先将检查点原文交核心完整验证，成功后才替换本区配置；不会修改上游输入、自动删除旧帧或重写时间戳。核心检查帧结构、会话、时间顺序和区间状态的内部一致性；续接数据需沿用原米制坐标系及原时钟。

输入配置修改会清本区结果。上游变化只使依赖该来源的本区结果失效；其他来源和原统计结果分别保留。后来的配置、文件导入或来源选择会取消旧准备，迟到操作不会覆盖新草稿。

## 原观测联合计算和恢复

“测量并统计证据区间”直接读取上方普通测量的原始 NDJSON 和本区配置，支持 pixel、ground 及各自恢复起点，不需要先运行普通测量。测量、法向证据门计数和区间配对共同提交，失败不会提交部分帧。

联合模式保留独立结果槽、回放滑块和当前帧测量行，并复用本区的区间和侧别表。通过“显示结果”选择“独立下游”或“原观测联合”；两个模式的结果和导出入口对应，联合运行不会覆盖普通测量、其他分析或独立下游报告。重新计算相同原文的普通测量不会清除联合结果；修改原始测量输入使联合结果失效，修改本区配置使两个结果槽都失效。

“下载完整联合区间结果”包含 measurement、transit 整批帧及同一末帧完整检查点。“保存所选帧完整联合区间检查点”按联合滑块重放原观测前缀，保存当前所选帧，不使用整批末帧代替。检查点格式为 `moonground.evidence-transit-analysis`，包含旧 session 完整检查点及 `moonground.evidence-transit` 完整检查点。

“载入完整联合区间检查点”先将完整原文交核心验证，再用返回的两个 canonical resume 文档重新验证联合恢复起点。全部成功后，页面一次性回填普通测量首行与本区配置，清除依赖旧输入的结果；添加更晚的原始观测后直接点击联合按钮继续，无需手工配水位。损坏、错配或错误格式的检查点不会替换已有输入和显示。联合回放和保存准备期间的新编辑、模式或计算选择会取消旧操作。

## 健康门控下的原观测联合通行

在“健康门控与法向证据联合分析”中点击“健康证据通行示例”，即可从原始目标和固定地标观测共同计算测量、法向证据过线与区间通行。首行 `analysis` 是原始“测量＋证据区间”配置字符串，`health` 是原始地标配置字符串；本入口不读取其他统计配置框，也不自动转换旧门控或证据过线首行。示例见 [evidence-guarded-transit.ndjson](../examples/evidence-guarded-transit.ndjson)。

“显示结果”在“证据过线”和“证据通行”之间切换，各自保留独立报告与滑块，共用健康时序、目标测量和法向侧别表。运行不会覆盖另一结果槽；只有实际替换共享原始输入才使依赖旧输入的结果失效。导出按钮对应当前模式，避免保存另一模式的检查点。

只有当前地标状态确认 Healthy 才处理目标。健康阻断、缺测与显式标定替换通过空测量帧取消待入口并关闭旧片段，累计完成数保留；恢复后需要新片段预热。示例包含短区间完成、健康阻断取消长区间待入口，以及第二次标定切换取消恢复后的待入口。

“下载完整健康证据通行结果”保存整批帧和末帧检查点；“保存当前帧健康证据通行检查点”重放当前滑块之前的原始帧前缀，保存所选水位。完整检查点格式为 `moonground.evidence-guarded-transit`，同时拥有测量、法向证据通行和地标健康状态。导入先将检查点原文交核心完整验证，成功后才一次性把完整 canonical resume 写入共享输入，不拆分各组件，也不改写观测时钟。添加更晚的配对观测或标定替换控制行后，使用同一证据通行入口续接。

错误输入或检查点保留已有有效显示和输入。新编辑、文件导入或运行选择会取消旧准备，迟到示例、文件和计算不能覆盖新草稿。普通测量及原观测联合区间面板仍各自独立。

## 与已查生态能力的关系

本批核对限于 Mooncakes 官方搜索与以下公开 API：[MBMOT 0.3.1 analytics](https://mooncakes.io/docs/python123-ops/mbmot@0.3.1/analytics)、[Moon-Kalman 0.2.1](https://mooncakes.io/docs/Lyllyl789/moon-kalman@0.2.1)。前者提供过线、区域转换及按帧停留，后者提供协方差、ConfidenceBand 和滤波检查点。所查 API 未见“法向协方差确认的双门通行＋原始时钟观测区间＋完整独立检查点”这一组合；该结论不覆盖整个 registry。

健康门控联合通行另核对了 [Moon-Kalman 0.2.1](https://mooncakes.io/docs/Lyllyl789/moon-kalman@0.2.1) 与 [Fiducial Marker 0.1.1](https://mooncakes.io/docs/2515050242/fiducial_marker@0.1.1) 的官方 API。前者的 OperationalMonitor、FilterCheckpoint 覆盖滤波健康与滤波状态恢复，后者提供 CameraCalibrator、ExtendedKalmanFilter6DOF 及协方差能力。在这些版本与已查页面中，未见固定地标标定健康、法向协方差确认的双门通行和原始目标测量共同提交、整体恢复的直接对应接口。基础标定和滤波能力存在交集，此处结论只针对已查组合。
